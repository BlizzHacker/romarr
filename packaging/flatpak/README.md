# Flathub: `app.romarr.ROMarr`

ROMarr as a desktop app for Linux, Steam Deck and ChromeOS (Linux
development environment). `romarr-desktop.py` starts ROMarr's own server on
`127.0.0.1` only and opens it in a native GTK 4 / WebKitGTK 6 window from the
GNOME runtime, so nothing is reachable from the network and no browser is
needed. `romarr-desktop --headless` serves without a window (Steam Deck game
mode, SSH, or your own browser).

| File | Purpose |
|---|---|
| `app.romarr.ROMarr.yml` | Flatpak manifest (GNOME 51 runtime, release tarball pinned by sha256) |
| `python3-requests.json` | `requests` and its wheels, generated by `flatpak-pip-generator` |
| `romarr-desktop.py` | Loopback server + window launcher |
| `app.romarr.ROMarr.desktop`, `.metainfo.xml`, `.svg` | Desktop entry, AppStream metadata, icon |

Per-user state lives in `~/.var/app/app.romarr.ROMarr/data/romarr/`. The
library defaults to the first existing `~/Emulation/roms` (EmuDeck),
`~/retrodeck/roms` or SD-card `Emulation/roms`, else `~/Games/ROMs`;
`ROMARR_LIBRARY` overrides it on first start. An inherited `LIBRARY_PATH` is
ignored, because on a desktop it is usually the linker search path.

## Build and lint locally

Flathub's own toolchain (`org.flatpak.Builder`) was used for the build and every
lint below passed on 2026-11-15:

```bash
flatpak install -y flathub org.gnome.Platform//51 org.gnome.Sdk//51 org.flatpak.Builder
flatpak run org.flatpak.Builder --user --install --force-clean --sandbox \
  --compose-url-policy=full --mirror-screenshots-url=https://dl.flathub.org/media/ \
  --repo=repo builddir app.romarr.ROMarr.yml
ostree commit --repo=repo --canonical-permissions --branch=screenshots/x86_64 \
  builddir/files/share/app-info/media
flatpak run --command=flatpak-builder-lint org.flatpak.Builder manifest app.romarr.ROMarr.yml
flatpak run --command=flatpak-builder-lint org.flatpak.Builder repo repo
flatpak run --command=flatpak-builder-lint org.flatpak.Builder appstream app.romarr.ROMarr.metainfo.xml
desktop-file-validate app.romarr.ROMarr.desktop
flatpak run app.romarr.ROMarr            # window
flatpak run app.romarr.ROMarr --headless # server only
```

Run once: the window opened ROMarr's set-your-password screen, `/api/health`
answered `{"ok": true}`, and the state file landed in `~/.var/app/...`.

To regenerate the Python sources after a dependency bump:
`flatpak-pip-generator --runtime org.gnome.Sdk//51 --output python3-requests requests`.

## Submit to Flathub

1. Fork <https://github.com/flathub/flathub> and create a branch from its
   `new-pr` branch (not `master`).
2. Copy every file in this folder except this README into the branch root.
3. Open a pull request against `new-pr` titled `Add app.romarr.ROMarr`.
   Reviewers build it with the same commands as above (`bot, build`).
4. Expect questions on two points and answer them in the PR:
   - `--filesystem=home` plus `/run/media`, `/media`, `/mnt`: ROMarr files games
     into a library folder the user picks (EmuDeck's `~/Emulation/roms`, an SD
     card, a NAS mount) and must read completed downloads wherever the download
     client writes them. A portal cannot express a long-running server writing
     into a chosen tree.
   - What it downloads: ROMarr ships no games or BIOS; it automates the user's
     own indexers and download clients, like Sonarr/Radarr. The metainfo says so.
5. After the PR merges, Flathub creates `flathub/app.romarr.ROMarr`. Claim the
   verified badge by publishing the token Flathub gives you at
   `https://romarr.app/.well-known/org.flathub.VerifiedApps.txt`.
6. New ROMarr releases: Flathub's external-data-checker reads the GitHub release
   API (see `x-checker-data` in the manifest) and opens a bump PR on its own.
   Add a `<release>` entry to the metainfo in the same PR.
