ROMarr Privacy Policy

Updated November 15, 2026.

ROMarr manages your game library on your device or a server you choose. This policy describes the official ROMarr application and its desktop clients. Connected servers, providers, plugins and emulators have their own operators and privacy practices.

Your local data

The ROMarr backend stores library records, settings, download state, reports and logs in its configured data directory. Settings may include server addresses, credentials, tokens or API keys. Keep this directory and its backups private.

On Android, the bundled backend and imported files use the app's private storage. The app imports files you explicitly select through Android's document picker. Saved server profile names and addresses and WebView sessions are held in app storage. Android cloud backup and device-transfer extraction are excluded by the current app configuration. A selected local game file can be handed to an emulator you choose using a temporary Android file permission.

The Windows client stores desktop preferences locally and uses separate browser profiles for different server origins. Clearing a profile removes that profile's browser session data.

Network requests and connected services

A remote server receives the requests you make to manage its library, including authentication and library-management information. The server operator controls that server's storage, access and logging. Use servers you trust.

Release checks are enabled by default and contact GitHub to check for updates; they can be disabled in settings. Online searches, metadata lookups, downloads, peer connections and optional integrations contact the services configured for those features. Recipients may receive your IP address, query terms, file identifiers or hashes, and credentials needed for the selected service. Downloading optional tools contacts their hosts. The publisher does not control other operators' retention or use of their records.

Native Android remote profiles require HTTPS and reject invalid certificates. Backend integrations can use operator-configured network addresses, including HTTP where supported; this policy does not promise encryption for every integration. Choose secure endpoints and avoid sending credentials over untrusted networks.

Scans, reports and support

File reports remain in the backend data directory. A report review may create a temporary private file snapshot. An enabled ClamAV service can receive file bytes; the optional MWM integration receives a scan path and authenticated request. VirusTotal integration checks a file hash and does not upload the game file through that lookup.

Nothing is automatically posted to GitHub as a support issue. An issue you explicitly submit may contain the text and report evidence you reviewed. Game files and local report notes are not attached by default. Remove credentials, private addresses and personal filenames before sharing diagnostics or screenshots publicly.

Advertising and permissions

ROMarr includes no advertising or analytics SDK and no in-app purchase SDK. We do not sell personal information through ROMarr. It does not request location, contacts, camera, microphone or broad storage access. Internet access supports servers, updates and configured online features. An AndroidX signature-only permission supports internal receiver isolation.

Retention and removal

You control the local backend data directory and can remove it after saving anything you want to retain. Clearing Android app storage or uninstalling normally removes private app data. Exported files, copies opened in other apps, remote server records and third-party service records are not removed by uninstalling ROMarr. Contact the relevant server or service operator about those records. Public GitHub submissions are subject to GitHub's controls and retention.

Contact

For privacy questions or deletion requests, email me@romarr.app. We can help with data we control; remote server and service operators handle records held by them. For general project questions, use ROMarr project support. Do not post private records or credentials in a public issue. For security reporting, follow the project security guidance.
